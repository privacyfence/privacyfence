Enterprise

One gateway for the whole organization, or one for yourself.

PrivacyFence runs for one person on their own computer, or once on a Linux server your organization controls, where everyone signs in through your identity provider. Both are the same open-source software, fully featured, and neither sends data through a PrivacyFence-operated server. When an organization server uses PrivacyFence's built-in sign-in apps, only the sign-in redirect passes through the PrivacyFence relay, and an organization can use its own apps instead.

PrivacyFence 7 deprecates desktop mode, and PrivacyFence 8 removes it. Desktop installs keep working through 7.x, without the built-in apps. Move to the Docker image on your computer or to an organization server (moving to organization mode).

In both modes, connector credentials stay with PrivacyFence and never reach the AI client. Desktop mode is described in Getting started, the difference in trust in Security and compliance.

Before you start

Prerequisites for an organization deployment.

A Linux server

Docker Engine 24 or newer with the Compose plugin 2.24 or newer. Without Docker: Python 3.11 or newer and systemd, as in the deployment guide. Do not install the desktop .deb on this host.

A hostname and TLS

A public hostname with DNS pointing at the server, and a certificate for it. If people will use claude.ai, ChatGPT on the web or Gemini Enterprise, the hostname must be reachable from the internet, because they connect from Anthropic's, OpenAI's and Google's servers.

HTTPS in front

The Docker files bring Caddy, which gets the certificate itself. With nginx or another proxy, the deployment guide has the settings; PrivacyFence trusts forwarded headers only from the proxy addresses you list.

Your identity provider

People sign in through your organization's OpenID Connect identity provider, or, for a small Google Workspace team, through PrivacyFence's built-in Google sign-in, which needs nothing registered at Google and admits only verified Workspace accounts. You name the admins by verified email or by a group claim.

Connector apps

PrivacyFence ships its own apps for Google, Slack, Salesforce, Atlassian and Miro, so an organization server, or the Docker image on your own computer, connects them with nothing to register. An organization may register its own app with any of them instead and upload it on the Admin page; its own apps never touch the relay. Each person then connects their own account. The server needs outbound HTTPS to the services' APIs and, for the built-in apps, to oauth.privacyfence.eu.

The Admin page

Administrators run the server from the Admin page: which services are offered and which app each uses, who may sign in, step-up, scoped tokens, audit forwarding and the install-wide privacy filter. Every change that alters what the server does asks for a passkey and is recorded in the audit log. The server address, the identity provider and the admins are set in the environment, not on the page.

The prerequisites in full, and the reverse proxy settings, are in the organization deployment guide.

Evaluating it

Open source, with no commercial offering.

PrivacyFence is published under Apache 2.0 by a private person. There is no paid tier or support contract: questions and bugs go to GitHub issues or info@privacyfence.eu, and vulnerabilities to the security policy.

If a data protection officer will review the rollout, AI assistants and the GDPR maps the GDPR principles to what PrivacyFence does, and where the answers for a DPIA are.

Before a rollout, read what PrivacyFence does not claim, and plan for it: pin a reviewed release and give someone the job of tracking new ones.
