PrivacyFence · feature/data-sync

Data sync manual checks

Nothing has to be done before the implementation starts. These four checks come after the last phase merges into feature/data-sync, while its pull request is open. Each one ends with a line to paste into the pull request.

0 of 0 steps done

Before implementation

No steps. /implement can start right away.

After implementation

1. Run one real recipe end to end, locally and unattended

about 45 min

CI fakes every connector. Only a real run shows the rules, the personal-data checkbox, the export files, grist_update_csv and the Peek upload working together with no approval card.

Paste into the PRma1 local end-to-end: PASS (or FAIL with the step and the message), plus which source you exported from.

2. Sign in and run the recipe against an organization-mode server

about 45 min

The OAuth sign-in, the one-time export link and the upload slot through a reverse proxy can only be proven against a real organization server and identity provider.

Paste into the PRma2 org-mode run: PASS (or FAIL with the step and the message), plus the identity provider you used.

3. Register the privacyfence-sync trusted publisher on TestPyPI and PyPI

about 10 min

A trusted publisher belongs to one PyPI project. Without these two, the new publish jobs fail at the next stable release. The main privacyfence package still publishes, because the sync jobs run after it.

Paste into the PRma3 trusted publishers: TestPyPI done, PyPI done

4. Apply the new required checks to the main ruleset

about 5 min

The PR adds the two "Sync client" checks to the script's list, but GitHub only requires them once the script applies the list to the ruleset.

Do this right after the PR merges, not before. Applied earlier, it would block every other open PR, because their runs never report the new checks.

Reportma4 required checks applied to main (and releases/** if it exists), as a comment on the merged PR.
