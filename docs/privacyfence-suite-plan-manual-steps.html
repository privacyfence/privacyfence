PrivacyFence suite setup steps

Two things to do before /implement builds the suite, and four checks after it, before the pull request merges. Your ticks are saved in this browser.

Before implementation

1. Create the repository with its profile and this plan

about 10 min
mb1-create-repo

Done when the plan opens in the new repository, main has README.md, LICENSE and .claude/toolkit.yaml, and a Claude Code session can clone it.

2. Release the three upstream changes, with public images

about 30 min, after their PRs merge
mb2-upstream-releases

Done when the latest GitHub release of each repository mentions its features (PrivacyFence: PRIVACYFENCE_PEEK_AUTO_PROVISION and PRIVACYFENCE_OIDC_CLIENTS; Peek: PEEK_OIDC_ISSUER_URL and PEEK_PROVISIONING_KEY_FILE; grist-provisioner: PROVISIONER_KEY_FILE), and all three docker pulls work anonymously.

After implementation

Use the feature branch named in the pull request. Each check ends with a line to paste into the PR.

3. Run the localhost stack on your own computer

about 15 min
ma1-localhost

Report ma1-localhost: pass, or fail at step N: <what you saw>.

4. Deploy caddy-google on a server

about 45 min
ma2-caddy-google

Report ma2-caddy-google: pass, or fail at step N: <what you saw>.

5. Deploy caddy-idp with your own identity provider

about 45 min; skip if you have none
ma3-caddy-idp

Report ma3-caddy-idp: pass, skipped (no IdP), or fail at step N: <what you saw>.

6. Start nginx-google with a real certificate

about 20 min
ma4-nginx-google

Report ma4-nginx-google: pass, or fail at step N: <what you saw>.
