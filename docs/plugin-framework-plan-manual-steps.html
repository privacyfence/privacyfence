Plugin framework: your manual steps

Only two things in this build need you: one registration before /implement starts, and a hands-on smoke test once the pull request is open. Everything in between runs in Claude Code sessions without waiting for you. Ticks are saved in this browser only.

Run the build with /implement https://github.com/privacyfence/privacyfence/blob/plan/plugin-framework/docs/plugin-framework-plan.md after finishing Before implementation. The orchestrator asks you once whether it is done.

Before implementation

mb1 · Register the SDK as a pending trusted publisher

~10 min

The new privacyfence-plugin-sdk package is published by publish-pypi.yml with OIDC trusted publishing, the same as privacyfence itself (ADR 0020). PyPI will not create a project from a workflow unless a pending publisher exists. Without this, the first stable tag after the merge fails the SDK publish jobs. No secret is involved.

Reference: docs/releasing.md, Publishing to PyPI. It describes the same registration for the main package.

  1. Sign in to TestPyPI and open test.pypi.org/manage/account/publishing/.You see Publishing, with a form titled Add a new pending publisher and a GitHub tab.
  2. On the GitHub tab, fill in the form:
    FieldValue
    PyPI Project Nameprivacyfence-plugin-sdk
    Ownerprivacyfence
    Repository nameprivacyfence
    Workflow namepublish-pypi.yml
    Environment nametestpypi
  3. Click Add.The pending publisher appears in the list under the form, naming privacyfence-plugin-sdk.
  4. Sign in to PyPI and open pypi.org/manage/account/publishing/. It is a separate registration from TestPyPI, even with the same login.
  5. Fill in the same values, except Environment name pypi, and click Add.The pending publisher appears in the list.

Done when both test.pypi.org and pypi.org list a pending publisher for privacyfence-plugin-sdk: owner privacyfence, repository privacyfence, workflow publish-pypi.yml, and environment testpypi or pypi respectively. Then reply "done" to the orchestrator.

After implementation

Do these once the orchestrator has opened the pull request. Its body lists them as unchecked boxes. Use a machine with a packaged PrivacyFence install (a source checkout cannot run plugins), Google Calendar connected, at least two events today, and an AI client connected to PrivacyFence.

ma1 · Smoke-test the today plugin

~45–60 min

CI cannot drive a packaged install with a real Calendar sign-in, a passkey prompt and a real administrator-only plugins directory. This walk-through touches every part of the framework once.

The same steps, kept with the code: examples/plugins/today/README.md on the feature branch.

OSPlugins directory (administrator-only)
Linux/usr/local/lib/privacyfence/plugins
macOS/Library/PrivacyFence/plugins
WindowsC:\Program Files\PrivacyFence Plugins
  1. In a checkout of the feature branch, build the plugin with the crash tool: 
    git fetch origin feature/plugin-framework && git checkout feature/plugin-framework
python3 -m pip install -e ".[dev]"
python3 scripts/build_example_plugin.py today --with-crash-tool --out dist/plugins
dist/plugins/today/today-plugin --self-test
    The last command prints today ok protocol 1.0.0. On Windows, run dist\plugins\today\today-plugin.exe --self-test.
  2. Copy the today folder into the plugins directory as an administrator: 
    # Linux
sudo mkdir -p /usr/local/lib/privacyfence/plugins
sudo cp -R dist/plugins/today /usr/local/lib/privacyfence/plugins/
sudo chown -R root:root /usr/local/lib/privacyfence
# macOS
sudo mkdir -p /Library/PrivacyFence/plugins
sudo cp -R dist/plugins/today /Library/PrivacyFence/plugins/
sudo chown -R root:wheel /Library/PrivacyFence
# Windows (PowerShell as Administrator)
New-Item -ItemType Directory -Force "C:\Program Files\PrivacyFence Plugins"
Copy-Item -Recurse dist\plugins\today "C:\Program Files\PrivacyFence Plugins\"
  3. Check that the trust check refuses an executable other users can write: make it group-writable (Linux or macOS: sudo chmod g+w …/plugins/today/today-plugin; Windows: in the file's Properties → Security, give Users Modify). Open Settings → Plugins and click Rescan. today shows executable is writable by non-administrators. Undo the change (sudo chmod g-w …, or remove the Modify grant) and Rescan again. The reason disappears.
  4. Click Review and enable on today. The dialog lists seven tools with their gates (today_status auto, today_refresh auto, today_list_events review, today_add_note popup, today_clear_notes popup and destructive, today_publish popup, today_crash auto). It also shows "Writes may run without asking", the source operation calendar.list_events, and pages: yes. Click Enable; you are asked for your passkey. Afterwards the state is running.
  5. Ask the AI client to call today_status, then today_refresh. Then click Export Audit Log… in Settings and open this week's file. Neither call shows a card. The audit export has a plugin_source row with connector plugin:today and tool calendar.list_events, whose summary holds the calendar id, the time range and a byte count, and no event titles.
  6. Ask for today_list_events. Approve the card. A review card shows a table of today's events, and the AI receives exactly that table. Ask again and choose Always allow → "this calendar" on the card. A third request shows no card. A request with another calendar_id shows a card again.
  7. Ask for today_add_note on one event, approve the popup card, then ask for the identical note again. The second request opens a new card. An approved write is single-use.
  8. Ask for today_publish. Approve the popup, then the confirmation card. The confirmation card shows a heading and a diff, and asks for your passkey. Approve it, then click Open page next to today in Settings. The page shows today's events and your note, the raw manifest in a code block, and "cookies: not readable".
  9. Sign Google Calendar out in Settings → Connectors and reload the plugin page. The page shows a stale-data banner. Sign back in, ask for today_refresh, and the banner goes away.
  10. Ask for today_crash five times, waiting for the plugin to come back between calls. After the fifth, Settings shows today disabled with crashed 5 times in 10 minutes. Use Review and enable again.
  11. Rebuild (step 1, without --with-crash-tool) and copy the new today-plugin over the installed one as an administrator. Click Rescan. today is disabled with executable or manifest changed, enable again until you review and enable it again.
  12. Click Delete this plugin's data and confirm with your passkey. Then delete the today folder from the plugins directory as an administrator and click Rescan. today disappears from Settings. The AI client no longer lists any today_* tool. No plugin-data/today folder remains under PrivacyFence's data directory.

Report back in the pull request: tick ma1 and paste one line per step, for example ma1: 1 pass · 2 pass · 3 pass · … · 12 pass (Linux 5.x, packaged). For a failing step, add what you saw instead.

ma2 · Repeat steps 1–4 on a second OS

~20 min

The plugins directory and the administrator-only check differ per OS (POSIX ownership on Linux and macOS, ACLs on Windows), and the unit tests mock them. If ma1 ran on Linux, use macOS or Windows here.

  1. On a second OS with a packaged install, do ma1 steps 1 and 2 (build and copy as administrator).
  2. Do ma1 step 3 (the writable-executable refusal, then undo).The reason appears and then clears after the undo and a Rescan.
  3. Do ma1 step 4 (review and enable with the passkey), then ask for today_status.The state is running and the AI gets a status answer.
  4. Click Delete this plugin's data, then remove the folder as an administrator and Rescan.

Report back in the pull request: tick ma2 and paste ma2: macOS|Windows · 1 pass · 2 pass · 3 pass · 4 pass.
