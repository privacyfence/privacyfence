Microsoft Connectors Checklist

Everything only you can do for the Outlook Mail, Outlook Calendar, Outlook Contacts, OneDrive and To Do connectors. Do the "Before" items before you run /implement. The orchestrator stops once, after phase p04, for the "At the pause" item. Do the "After" item before the pull request merges. Ticks are saved in this browser only.

Part 1

Before implementation

About 75 minutes in total. Nothing here needs the new code.

mb1 · Create a dedicated QA Microsoft account

~10 min

Every seed item, every recorded fixture and the final smoke test live in this account. It must share nothing with your own mailbox.

Done whenYou can sign in to outlook.live.com with the new account, and it has OneDrive and To Do.

mb2 · Register the "PrivacyFence QA" app in Microsoft Entra

~20 min

This gives the client id that the QA bundle carries. Use any Microsoft account you control as the owner; it does not have to be the QA account. Registering an app with a personal account needs a directory, which a free Azure account gives you.

Done whenThe app's Overview page shows an Application (client) ID, and Authentication lists http://localhost/callback and http://localhost:53685/callback under "Mobile and desktop applications".

mb3 · Seed the QA account

~35 min

The recorder finds each item by its exact name and refuses to record anything without the [QATEST] tag. Copy names character for character. Every body is synthetic. The full reference is plan §3.5.

Done whenEvery item above exists with exactly the listed name.

mb4 · Add the Microsoft sections to the runner's QA manifest

~5 min

This is on the self-hosted runner (privacyfence-test), as the runner user. The file is git-ignored and never leaves the runner. See connector-qa.md → Persistent QA state.

Done whenThe runner's qa_environment.yaml contains the outlook_mail, outlook_calendar, outlook_contacts, onedrive, onedrive_excel and todo sections. Then tell /implement that the "before" steps are done.
Part 2 · the one pause

At the pause after p04

/implement stops here and asks you to approve p04. By then, the sign-in code (p01), the Graph transport (p02) and the recorder checks (p04) are merged on feature/microsoft-connectors. You chose this pause, so the real sign-in flow mints the QA token.

gate · Sign the QA account in and put the token on the runner

~15 min

Do this on your development machine, a source checkout as in dev-vs-live-setup.md. The token file is a live credential: it only ever lives on that machine and the runner (ADR 0019).

Report back"approve p04: bundle and token installed on the runner, signed in as the QA account".
