Approval binding: the real-client check

One check with a real AI client, after every phase has merged into fix/approval-core-hardening and before its pull request merges. CI drives the gate with fake connectors only; this shows that a real re-issued call still finds its decision, and that a changed one does not.

ma1-real-client-deferred-round-tripA deferred approval is still collected, and a changed request gets its own cardabout 30 min

If any card field changed between two identical calls, the agent would loop on new cards; if the binding were too loose, a changed message could reuse your approval.

  1. Use a development machine or VM with no packaged PrivacyFence install, as docs/dev-vs-live-setup.md describes. Check out the feature branch: git fetch origin fix/approval-core-hardening && git checkout fix/approval-core-hardening.a clean checkout of the branch.
  2. Start the daemon from the checkout: ./scripts/dev_start.sh.the daemon log says it is listening on http://localhost:8765.
  3. Connect a Slack test workspace in Settings, following docs/slack-setup.md. Use a channel only you read, or your own DM.Slack listed as connected in Settings → Connections.
  4. Add PrivacyFence to Claude Code as docs/connect-claude-code.md says, and start a Claude Code session.claude mcp list shows PrivacyFence connected.
  5. Ask Claude Code: “Send the message ‘binding check A’ to <your channel> with slack_send_message.” Do not open the card for at least 40 seconds.Claude Code reports approval_pending and gives you a link.
  6. Open the link. Check the card shows binding check A. Click Allow once. Tell Claude Code the approval is done.Claude Code repeats the call and reports it sent; exactly one message ‘binding check A’ arrives in Slack, and no second card appears.
  7. Ask Claude Code to send ‘binding check B’ the same way and again leave the card alone for 40 seconds. Allow it. Then tell Claude Code: “Call slack_send_message again with the text ‘binding check C’ instead, reusing that approval.”‘binding check B’ arrives once. The ‘C’ call returns approval_pending with a new card showing ‘binding check C’, and nothing is sent until you decide. Deny it.
  8. Ask Claude Code to read the last 1 message of the channel (slack_get_channel_history, limit 1). Leave the card for 40 seconds, then allow it. Then ask it to read the last 20 messages.the 1-message read is released after your approval. The 20-message read gets a new card instead of reusing the first approval.
  9. Find a busy channel (one where messages arrive every minute or so). Ask Claude Code to read its last 5 messages, leave the card for 40 seconds, then allow it.either the read is released, or, if a new message arrived meanwhile, a new card appears showing the new content. Note how many cards it took; endless new cards on a quiet channel is a fail, a second card on a busy one is the intended behaviour.
  10. Open Settings → Audit log.for ‘binding check A’, an approval_pending row and an approved row with the same request id; for ‘C’, a separate approval_pending and rejected.
Report backPaste into the pull request: ma1: deferred write collected once — pass/fail; substituted write got a new card — pass/fail; wider read got a new card — pass/fail; busy-channel read — released after N cards. On any fail, include the audit rows.
