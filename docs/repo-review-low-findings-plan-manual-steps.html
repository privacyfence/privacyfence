Header rules checklist

Two jobs for after the last phase has merged into fix/review-low-findings and before you merge its pull request: create three Cloudflare header rules for privacyfence.eu, then check the live site. Nothing is needed before the work starts. Your ticks are remembered in this browser.

Work for issue #926 (WEB-9). Plan: repo-review-low-findings-plan.md.

After implementation

1. Create the three Cloudflare response-header rules

About 15 minutes. GitHub Pages cannot send headers, so Cloudflare adds them; the check that runs after each website deploy fails until these exist.

  1. Open dash.cloudflare.com, choose the privacyfence.eu site, then Rules → Transform Rules → the Modify Response Header tab → Create rule.

    You should see: a rule form with a name field, an expression editor and a header list. Cloudflare's own guide: Create a response header modification rule.

  2. Create rule one. Name: pf-security-headers-all. Click Edit expression and paste:

    (http.host eq "privacyfence.eu")
    Under Then, add three headers, each with the operation Set static:
    Header nameValue
    Strict-Transport-Securitymax-age=31536000; includeSubDomains
    X-Content-Type-Optionsnosniff
    Referrer-Policystrict-origin-when-cross-origin
    includeSubDomains also makes browsers insist on HTTPS for every subdomain of privacyfence.eu, including downloads.privacyfence.eu. If you run any subdomain that serves plain HTTP, tell me before you save, and leave that word out. Click Deploy. You should see: the rule listed as active.

  3. Create rule two. Name: pf-csp-site. Expression:

    (http.host eq "privacyfence.eu" and http.request.uri.path ne "/docs" and not starts_with(http.request.uri.path, "/docs/"))
    Under Then, one header, Set static: name Content-Security-Policy, value (one line): 
    default-src 'self'; script-src 'self' https://www.googletagmanager.com; style-src 'self'; img-src 'self' data: https://*.google-analytics.com https://www.googletagmanager.com; connect-src 'self' https://downloads.privacyfence.eu https://*.google-analytics.com https://*.analytics.google.com https://www.googletagmanager.com; font-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'
    Click Deploy.

  4. Create rule three. Name: pf-csp-docs. Expression:

    (http.host eq "privacyfence.eu" and (http.request.uri.path eq "/docs" or starts_with(http.request.uri.path, "/docs/")))
    One header, Set static: name Content-Security-Policy, value (one line). It differs from rule two only in allowing inline scripts and styles, which the documentation generator emits: 
    default-src 'self'; script-src 'self' 'unsafe-inline' https://www.googletagmanager.com; style-src 'self' 'unsafe-inline'; img-src 'self' data: https://*.google-analytics.com https://www.googletagmanager.com; connect-src 'self' https://downloads.privacyfence.eu https://*.google-analytics.com https://*.analytics.google.com https://www.googletagmanager.com; font-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'
    Click Deploy.

  5. Compare with the repository's copy. In a checkout of fix/review-low-findings run the command below, or read scripts/site_security_headers.py. The values above are generated from it; if they differ, the file wins, and please tell me.

    python3 scripts/site_security_headers.py

Report back

2. Check the live site

About 10 minutes. The automated tests stub Google Analytics, so only a real visit shows whether the policy blocks something it needs.

  1. In a checkout of fix/review-low-findings, run:

    python3 scripts/check_site_headers.py https://privacyfence.eu
    You should see: twelve [ ok ] lines (four headers on /, /docs/ and /download/) and the last line Site security headers match. If Cloudflare serves a cached copy without headers, wait a minute and run it again.

  2. Open privacyfence.eu in a private window with the developer console open (Console tab). Click Accept on the cookie banner.

    You should see: the banner closes, and no console message starting with “Refused to load” or “Refused to connect”. In the Network tab a request to googletagmanager.com/gtag/js succeeds.

  3. Click through /download/, /docs/ (switch the light/dark toggle, open one page with a table such as /docs/tools-reference/) and /releases/.

    You should see: the release cards and download counts load, the docs navigation and search open, the table is right-aligned where it was, and the console stays free of “Refused to …” messages.

  4. Check that the site cannot be framed: in the console on any other site (for example a blank tab), run the line below.

    document.body.append(Object.assign(document.createElement("iframe"), {src: "https://privacyfence.eu/"}))
    You should see: an empty frame and a console error saying the site “refused to connect” or that frame-ancestors 'none' blocked it.

If a step shows a “Refused to …” message, copy the console line into the pull request and stop: the policy needs a change in the repository first, and the rules above must then be edited to match.
