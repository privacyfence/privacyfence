`README.md` embeds `gmail-read-thread.png` through a
`raw.githubusercontent.com/.../main/docs/images/screenshots/…` URL, so a change to it shows up there
once it is on `main`. `scripts/build_site.py`'s `STATIC` map copies every file above into the
site's `assets/`, and a push to `main` touching `docs/images/**` redeploys the site.

## Regenerating

```bash
.venv/bin/pip install -e ".[test]"   # playwright is in the [test] extra
.venv/bin/python scripts/qa_readme_screenshots.py [--only all|gmail|sheets|slack|salesforce|jira|telegram] [--chromium-path /path/to/chrome]
```

The script starts the real embedded web server (`WebServer`) in-process on `127.0.0.1:18701` with
a temporary data directory. No real connector account or credentials are involved. It signs in
with a one-time bootstrap link and drives headless Chromium in the light color scheme, writing
every file straight into this directory.

Each image is one approval card. The script calls the real connector tool (`gmail_get_thread`,
`drive_sheets_write_range`, `slack_get_thread_replies`, `salesforce_get_record`, `jira_get_issue`,
`telegram_get_messages`) against a fake client that returns synthetic content, so each card is
what the real gate builds for that call (PII highlighting, the "AI will receive" list, the stated
reason and the calling AI system included). It opens each card from `/approvals` → Review, the way
a person reaches it, at 2× device scale and a width of 1000.

`--only` defaults to `all`. Pass `--chromium-path` if Playwright's own Chromium is not installed
(`playwright install chromium`).

Regenerate when the approval card's visual design changes meaningfully, not on every card
change. Never hand-edit an image here.

## Maintenance

- Keep only screenshots that current documentation or the website references. When the UI
  changes, regenerate the affected image and delete obsolete ones rather than keeping historical
  copies here.
- Renaming or removing a file here also means updating `scripts/build_site.py`'s `STATIC` map
  and every page in the table above.
- Never capture real account data, tokens, email addresses, tenant identifiers, or private
  document/message content.
