Atlassian mentions: checks on a real site

These checks go with the feature/atlassian-user-names pull request. Nothing has to be done before implementation starts. When the PR is ready, do both checks below on the QA Atlassian site. Use the account already set up for connector QA (see connector-qa.md).

Before implementation

Nothing. Jira's user API needs only the read:jira-user scope, which every existing Atlassian token already has.

After implementation

1. Read an issue and a page that mention someone

About 10 minutes · manifest id ma1-verify-reads

  1. Run PrivacyFence from the PR branch on your development machine (dev-vs-live-setup.md). Settings should show Jira and Confluence as connected.
  2. On the QA Jira site, open a PFQA issue whose summary contains [QATEST]. Add a comment that mentions a second QA account (type @ and pick them). Note that person's name.
  3. Ask your AI client to call jira_get_issue on that issue. On the approval card, the Comments table should show @<their name>. Approve it.
  4. In the tool result, the comment body should contain @[<their name>](<account id>).
  5. On the QA Confluence space, edit a [QATEST] page and add an @mention of the same person. Publish it.
  6. Ask the client to call confluence_get_page on that page. The approval card should show the author's name (not a long id) and @<their name> in the page body. Approve it. The result should have author as a name, author_id as the id, and a mentions entry for the person.
  7. Ask the client to call jira_find_users with part of that person's name. Their account_id should be listed, and no email address.

Report back in the PR: ma1: pass, or ma1: fail at step N with what you saw instead. Leave out real names.

2. Write a mention and check the notification

About 10 minutes · manifest id ma2-verify-mention-writes

  1. Ask the client to post a comment on the same PFQA issue that mentions the second QA account. The client should look them up with jira_find_users and write @[Name](accountId).
  2. On the approval card, the Mentions row should show the person's real name, as Jira holds it. Approve it.
  3. Open the issue in Jira. The comment should show a real mention chip, not the literal @[…](…) text.
  4. Sign in as the second QA account, or check its mailbox. It should have a "mentioned you" notification for that comment.
  5. Ask the client to create a page in the QA space whose body mentions the same person. The approval card should have a Mentions row with their name. Approve it, open the page, and check that the mention chip is there and the person was notified.
  6. Negative check: ask the client to comment with a made-up id, such as @[Someone](5b10ac8d82e05b22cc7d4ef0). The call should fail with Unknown Atlassian account id(s), and no approval card should appear.

Report back in the PR: ma2: pass, or ma2: fail at step N with what you saw instead. Delete the test page afterwards by hand if you wish; PrivacyFence cannot delete Confluence content.
