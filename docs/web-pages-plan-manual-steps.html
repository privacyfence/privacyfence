Web pages: the steps only you can do

The Web pages connector publishes a single-file HTML page over SFTP to a web server you run and hands the AI client its link. Workers build and test it against an in-process SFTP server; these checks prove it against a real Ubuntu server and real AI clients. Ticks are remembered in this browser.

Before implementation

Nothing to do. You can run /implement on the plan straight away.

After implementation

Do these once the orchestrator has opened the pull request from feature/web-pages. The PR lists both as unchecked items. The setup guide is written in the last phase, so it exists only on the feature branch until the PR merges: docs/web-pages-setup.md on feature/web-pages.

1. Organization deployment, claude.ai and Claude Code

about 60 min

Needs a test organization deployment you can restart, an Ubuntu 24.04 machine for the pages (it may be the same host), and DNS for a second hostname such as pages.acme.example.com. Use a test deployment, not production.

  1. Point a DNS record for the pages hostname at the web server machine.

    You should see it resolve with dig +short pages.acme.example.com. Use a different hostname from PrivacyFence's own.

  2. On the web server, create the SFTP-only account and the folder:

    sudo useradd --system --create-home --home-dir /var/lib/pf-pages --shell /usr/sbin/nologin pf-pages
sudo install -d -o pf-pages -g pf-pages -m 755 /srv/pages

  3. Create /etc/ssh/sshd_config.d/pf-pages.conf with this content, then run sudo systemctl reload ssh:

    Match User pf-pages
    ForceCommand internal-sftp
    AllowTcpForwarding no
    X11Forwarding no
    PermitTTY no

  4. Add the site to Caddy (/etc/caddy/Caddyfile) and run sudo systemctl reload caddy. The nginx version is in the setup guide.

    pages.acme.example.com {
    root * /srv/pages
    file_server
    header {
        Content-Security-Policy "sandbox allow-scripts allow-popups allow-popups-to-escape-sandbox allow-forms allow-modals allow-downloads"
        X-Content-Type-Options nosniff
        Referrer-Policy no-referrer
        X-Robots-Tag "noindex, nofollow"
        Cache-Control no-cache
    }
}

    Check with curl -sI https://pages.acme.example.com/: a 404 that carries the content-security-policy: sandbox … header, and no directory listing.

  5. Print the web server's host key and keep the line for the next step: cat /etc/ssh/ssh_host_ed25519_key.pub

    One line starting ssh-ed25519 AAAA. It is public; it is not a secret.

  6. On the PrivacyFence server, install the feature branch into the venv:

    sudo /opt/privacyfence/venv/bin/pip install "git+https://github.com/privacyfence/privacyfence@feature/web-pages"

  7. Add the Web pages section to your bundle with --merge, then copy it into place as in Changing a bundle later:

    python3 build_org_bundle.py --merge -o org_config.json --sign-key ~/secure/org-signing-key.pem \
  --pages-sftp-host pages.acme.example.com --pages-sftp-user pf-pages \
  --pages-sftp-host-key "ssh-ed25519 AAAA…(line from step 5)" \
  --pages-remote-dir /srv/pages --pages-public-base-url https://pages.acme.example.com

    Take build_org_bundle.py from the feature branch's scripts/. Restart with sudo systemctl restart privacyfence-org.

  8. Get PrivacyFence's public key, from both places, and check they match:

    sudo -u privacyfence-org -H /opt/privacyfence/venv/bin/privacyfence-app --pages-public-key
journalctl -u privacyfence-org -b | grep "Web pages: publishing over SFTP"

    Both show the same ssh-ed25519 … privacyfence-pages line.

  9. On the web server, authorize that key for pf-pages:

    sudo install -d -o pf-pages -g pf-pages -m 700 /var/lib/pf-pages/.ssh
echo 'restrict ssh-ed25519 AAAA… privacyfence-pages' | sudo tee /var/lib/pf-pages/.ssh/authorized_keys
sudo chown pf-pages:pf-pages /var/lib/pf-pages/.ssh/authorized_keys
sudo chmod 600 /var/lib/pf-pages/.ssh/authorized_keys

  10. In claude.ai → Settings → Connectors, reconnect PrivacyFence so the new tools load. Start a chat, ask Claude for a small HTML artifact, then ask: “Publish this page with PrivacyFence Web pages.”

    The approval card shows Page, Address (with <new id>), Action, Size, Scripts and “Anyone with the link”, and the page's text. Approve. Claude answers with a link; open it in a private window.

  11. Ask Claude to change the page and publish it again.

    The card says “Replace the page first published …”; the link stays the same and shows the new version after a reload.

  12. Ask Claude to publish a page containing a made-up IBAN such as DE89 3704 0044 0532 0130 00.

    After you approve, a second “Are you sure?” confirmation appears for the detected personal data. Deny it; nothing is published.

  13. In Claude Code connected to the same deployment, ask it to write a page over 150 KB and publish it.

    It uses privacyfence_create_upload_slot, a PUT, then pages_publish_html with upload_id. Approve; the link works.

  14. Ask either client to list your pages, then to take one down.

    The list shows only your pages. Taking one down shows a card, and afterwards its link returns 404.

  15. Rebuild the bundle with a wrong --pages-sftp-host-key (any other server's key), restart, and ask for a publish. Then put the right key back and restart.

    After approval the client reports that the server presented a host key that does not match, and nothing appears in /srv/pages.

Report back: paste into the PR one line, for example ma1 org end-to-end: PASS (claude.ai, Claude Code, PII confirmation, wrong host key), or FAIL with the step number and what you saw.

2. Desktop install and Claude Desktop

about 30 min

Uses the same web server as item 1. A separate authorized_keys line is needed, because a desktop install has its own key.

  1. Open the green build.yml run the last phase dispatched on feature/web-pages (its URL is in the PR) and download your platform's installer from its artifacts.

  2. Install it on a test machine, not one with your everyday PrivacyFence.

    PrivacyFence starts and its companion icon appears.

  3. Open PrivacyFence Settings → Connectors.

    A Web pages row shows “Not configured” and a “Set up…” link.

  4. Click Set up… and fill Server, Port, Account, Server's host key, Folder on the server and Public address, using the values from item 1.

  5. Copy the line under “PrivacyFence's public key” and append it, prefixed with restrict , to /var/lib/pf-pages/.ssh/authorized_keys on the web server.

  6. Click Save and complete the passkey or sign-in check it asks for.

    The row changes to Connected and its link to “Change…”.

  7. In Claude Desktop, ask for a small HTML page and to publish it with PrivacyFence Web pages. Approve the card and open the link.

  8. Ask Claude to take the page down and approve.

    The link returns 404.

Report back: paste into the PR ma2 desktop end-to-end: PASS (<platform>), or FAIL with the step number and what you saw.
