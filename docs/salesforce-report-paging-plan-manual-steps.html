Salesforce report paging: your steps

These are the two things only you can do for issue #854. Do the first one before running /implement, and the second once the feature PR is ready. No step involves a secret.

Before implementation

1. Give the QA org a key column and a grouped report

about 15 min · mb1-qa-org-key-column

The live check pages the QA report by an auto-number column and reads a grouped report as one table. Without both, phase p2 stops.

  1. Sign in to the QA Salesforce org at login.salesforce.com, as the account that connector-live-check.yml uses. Do not use your production org.
  2. Open Setup → Object Manager → Account → Fields & Relationships. On your org that is https://<your-domain>.lightning.force.com/lightning/setup/ObjectManager/Account/FieldsAndRelationships/view. Click New.
  3. Choose Auto Number and click Next. Set Field Label to PF QA Number and Display Format to PFQA-{00000}, with starting number 1. Tick Generate Auto Number for existing records. Click Next, keep the default field-level security (visible to the QA user's profile), and click Save.

    You should see: the field PF_QA_Number__c in the list. Your [QATEST] Accounts now have values like PFQA-00001.

  4. Open the Reports tab, open PrivacyFence QA Report and click Edit. Add the column PF QA Number, then click Save & Run.

    You should see: the report still tabular, with at least 2 rows and a PF QA Number value in each.

  5. Click New Report, choose report type Accounts and click Start Report. Add the columns Account Name and PF QA Number, and under Group Rows add Billing City.
  6. Save it as exactly PrivacyFence QA Summary Report, in the same folder as the QA report and shared the same way, then click Run.

    You should see: rows grouped by Billing City. If your [QATEST] Accounts have no Billing City, one "-" group is fine.

  7. Optionally, compare with connector-qa.md, Seed: Salesforce. Phase p2 adds these two items there. The recorder finds the column by its label, PF QA Number, so the runner's qa_environment.yaml needs no edit.

Done when: "PrivacyFence QA Report" shows a PF QA Number column with values like PFQA-00001, and "PrivacyFence QA Summary Report" (grouped by Billing City, with PF QA Number) runs. Then tell the /implement session "mb1 done".

After implementation

2. Page a large report on your real org

about 30 min · ma1-real-org-paging

The QA org cannot hold 2,000+ rows, so this step checks the issue's three "verify first" items on a real report: sortBy is honoured, greaterThan works on your key column, and each run stops at 2,000 rows.

  1. Install the build of the feature PR. build.yml dispatched against feature/salesforce-report-paging produces it; the PR links the run. Alternatively, run from source per dev-vs-live-setup.md. Connect Salesforce to your real org as usual.
  2. In Salesforce, pick a tabular report with more than 2,000 rows that has a column with a unique value per row, ideally an Auto Number field. Note its total row count (the report's Record Count) and the column's API name, for example from the report's describe or the column name the tool error lists.
  3. Ask your AI client: "Run Salesforce report <id> with page_by <column> and follow next_cursor until it is null. Tell me each page's number, first_row and last_row, and whether any key value repeated." Approve each card.

    You should see: each card's Rows line reads "Page N: rows a–b, more pages follow", and the last one reads "…, last page". No card mentions "Cut off". The last page's last_row equals the report's record count.

  4. Spot-check the order. Page 1's first key is the smallest value of the column in Salesforce (sort the report by it in the UI), and page 2 starts right after page 1's last key.
  5. Repeat steps 3 and 4 with a summary report (grouped) that has more than 2,000 rows.

    You should see: the grouping columns as the first columns of each row, and the same count check passes.

  6. Try a non-unique column, such as Stage or Owner, as page_by.

    You should see: an error ("…is not unique…", "…did not advance…" or "…lost rows…"), and no rows and no further card.

  7. If your report's key is a record-ID column rather than an auto-number, try it too, and note whether it pages correctly. The docs currently say ID columns are not guaranteed.
