1. Proofread the built site

ID ma1-proofread-built-siteTime about 30 minutes

The browser tests check structure and layout. They cannot tell whether the copy reads well or claims more than PrivacyFence 7.0.0 does.

  1. Open the website-build runs for chore/website-7x and click the newest green run.

    You see the run summary, with an Artifacts section at the bottom.

  2. Under Artifacts, download website-build and unzip it.

    You get _site/ (documentation from the newest release tag) and _site-next/ (documentation from this branch).

  3. cd _site
python3 -m http.server 8000

    Open http://localhost:8000/install/. The header's dark button now says Install.

  4. Pick each answer in turn and check which result appears:

    ChoicesResult heading
    Just me · with Peek and GristThe suite, for one person on this computer
    Just me · PrivacyFence onlyPrivacyFence alone, for one person on this computer
    Organization · suite · own identity provider · CaddyThe suite with Caddy and your identity provider
    Organization · suite · built-in Google · CaddyThe suite with Caddy and the built-in Google sign-in
    Organization · suite · built-in Google · nginxThe suite behind your nginx, with the built-in Google sign-in
    Organization · suite · own identity provider with nginx or other, or built-in Google with otherNo ready-made suite configuration for this combination
    Organization · PrivacyFence only · CaddyPrivacyFence alone, with Caddy

    Exactly one result shows at a time. Under "Organization", the notes on built-in or own apps and on built-in Google sign-in follow your answers. Under "Just me", the warning about agents that can run docker shows.

  5. In your browser's developer tools, switch to a 390 px wide device and go through the picker once more.

    Nothing scrolls sideways except the code blocks, and every option label is readable.

  6. Read /download/, /enterprise/, /faq/, /connectors/slack/ and /connectors/google-workspace/.

    Every claim matches 7.0.0. No data passes through a PrivacyFence-operated server, and only the sign-in redirects of the built-in apps go through oauth.privacyfence.eu. Desktop mode is called deprecated, and "PrivacyFence 8 removes it" appears on /download/ and /faq/.

  7. On /relay-terms/, the "relay documentation" link opens docs/oauth-relay.md on GitHub. That is expected until the next stable release. In _site-next/ the same link goes to /docs/oauth-relay/.

Report back: tick the ma1 item in the pull request and add a comment such as ma1: pass or ma1: fail – /faq/ #modes says …, naming each page and sentence to change.

2. Connect Claude Code and Claude Desktop to single-user Docker

ID ma2-single-user-clientsTime about 20 minutesNeeds a Mac or Windows computer with Docker, Claude Code and Claude Desktop

The website and the updated connect guides now say both clients reach the Docker image at http://localhost:8765/mcp and sign in with a passkey. Only a real computer can show that.

  1. docker run --rm -p 127.0.0.1:8765:8765 \
  -v pf-data-check:/var/lib/privacyfence-org/.privacyfence \
  ghcr.io/privacyfence/privacyfence-org:latest

    The log prints Setup code: XXXX-XXXX. Open http://localhost:8765/login to set up your passkey. The separate pf-data-check volume keeps this test away from any real install.

  2. Open http://localhost:8765 (not 127.0.0.1), enter the code and create a passkey.

    You land in PrivacyFence, signed in as the administrator.

  3. On /connect, connect one service with a test account, for example Google with a throwaway account.

    The service shows as connected. This needs outbound HTTPS from the container to oauth.privacyfence.eu.

  4. claude mcp add --transport http --scope user privacyfence-check http://localhost:8765/mcp

    In Claude Code, run /mcp, choose privacyfence-check, sign in with your passkey and allow the consent page. Then ask for something that needs approval, such as a draft email, and approve it in PrivacyFence.

    The tools are listed, and the approval card appears in the browser.

  5. In Claude Desktop's connector settings, add a custom connector with the URL http://localhost:8765/mcp, leave the OAuth client ID and secret empty, click Connect and sign in with your passkey. Ask for one request that needs approval and approve it.

    The connector connects and the approval card appears. If Claude Desktop refuses a localhost address, that is a fail: report the exact message.

  6. claude mcp remove privacyfence-check
docker volume rm pf-data-check

    Stop the container first (Ctrl-C), and remove the custom connector in Claude Desktop.

Report back: tick the ma2 item in the pull request and comment ma2: Claude Code pass/fail, Claude Desktop pass/fail, with the operating system and any error text. A Claude Desktop fail means its Single-user Docker section in the docs and its website card are corrected in the same pull request.
