1. Create the auto-accept rules for the weekly sync

≈ 15 min

These rules are your configuration, not code. Without them, every export and every grist_update_csv in the scheduled run still shows a card.

  1. Use the long id from Settings, not the shorter one in the address bar (Grist setup).
  2. Or ask Claude to run salesforce_list_reports, which is auto-approved, and read the id column.
  4. How rules work: Approvals and policy.
  5. You should see the rule listed with the three document names. read covers grist_get_records, grist_export_records and grist_export_sql. update covers grist_update_csv and also grist_update_records, for those three documents only.
  6. It covers salesforce_run_report and salesforce_export_report for those reports.
  7. It covers reading files in that folder (drive_get_file_content, drive_download_file, drive_sheets_get_values).
  8. Each one should report auto-accept.

You chose to keep the PII gate. An export whose rows contain an email address, phone number or other personal data still shows a card, even with these rules. In a session that called privacyfence_begin_unattended_session, such an export is denied straight away (denied_unattended) instead of waiting, so the skill can report it and stop. That mode needs unattended_sessions.enabled in org_config.json.

2. Run each export once against real data

≈ 30 min

CI tests use fakes. Only your Grist server and Salesforce org can show whether SQL is allowed, how the real date filters behave and what the real cells look like.

  1. Settings → Connectors should show Grist and Salesforce as connected.
  2. You should get one card showing the row count, the first 20 rows and "Saved to". The tool result holds only rows, columns, sha256 and where the file went. The file starts with an id column, and dates read YYYY-MM-DD.
  3. The card should say 0 cells to change. Deny it. This shows an export goes back into Grist cleanly.
  4. One card with a "Report runs" line. The file's row count matches the report's total in Salesforce.
  5. [{"column": "LAST_UPDATE", "operator": "greaterOrEqual", "value": "2026-10-04"}]
    You should get only the rows changed since that date. If Salesforce rejects the column, use the name from reportMetadata.detailColumns in a salesforce_run_report result.
  6. You should get a one-column file with every id, which the sync uses to spot removals.
  7. Either one card that shows the query and its result rows, or the message "Grist refused the SQL query (HTTP 403)…". A 403 means your account cannot copy the whole document, or your OAuth sign-in doesn't cover SQL. Note which sign-in you used.
