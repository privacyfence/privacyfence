ma1-real-idp-org-flowsConsent page, provider connect, sign-in and IdP step-up on a real deploymentabout 45 min

The consent page is the fix for a client getting a token without the person seeing it; it only matters if a real IdP signs people in silently.

  1. On your test organization server (never production), install the branch: pip install --upgrade "git+https://github.com/privacyfence/privacyfence@fix/web-and-org-hardening" into the service's virtual environment, then restart the service, as the organization guide, Upgrade describes.the service is active and /login loads over HTTPS.
  2. In org_config.json, set "step_up": {"enabled": true} for this test (see Approvals and step-up) and restart. Do not enrol a passkey for the test user.Settings shows step-up on.
  3. Sign in at https://<your host>/login as test user A.you land on /approvals, signed in as A.
  4. On your computer: claude mcp add --transport http privacyfence-test https://<your host>/mcp, then run /mcp in Claude Code and authenticate.after the IdP sign-in, a PrivacyFence page “Allow Claude Code to use PrivacyFence as <A's email>?” naming the host Claude Code returns to (localhost). Nothing is connected yet.
  5. Click Allow.a short “Returning to …” page, then Claude Code reports PrivacyFence connected.
  6. Remove and re-add the server (claude mcp remove privacyfence-test, then step 4 again) as the same user.no consent page this time: the choice was remembered for A and this client.
  7. In Claude Code, ask for a write that needs approval (for example a Gmail draft). Open its card in the browser and click Allow once.“This approval needs extra verification” with a button Verify by signing in again. Clicking it sends you through a fresh IdP sign-in and back to /approvals?stepup=ok, and the write goes through.
  8. Take the id of any pending approval and open https://<your host>/api/approvals/<id>/stepup/idp?result=accept directly in the browser.405 Method Not Allowed, and the approval is still pending.
  9. Open /connect and connect Google (or Slack) for user A.the provider's consent screen, then “Connected” on /connect.
  10. Optional, if you have a second test user B: start /connect → Google as A, copy the provider's consent URL before finishing it, and open it in a private window signed in as B. Finish the consent there./connect shows the connection failed, and neither A nor B has a new Google connection.
  11. Turn step_up.enabled back to what it was and restart.the server is back to its normal configuration.
